# Project status — 0.25.0, 2026-11-15

Release 0.25.0 (2026-11-15) makes the pixel art scale cleanly. `redux/pixel_fit.py` contains a sprite in its space at the largest whole factor of its art size (fractional only below 1x); `Artwork.sprite` reduces a 2x-exported cell to its art pixels (exact) before a nearest-neighbour enlargement, so every art pixel is an even square, and can crop to a viewport. Drawing moved to screen pixels (`device_frame`, `device_rect`, `device_sprite` in the layout): the loading screen is laid out from the window, the carousel has its own clipped viewport across the full window width (more pennants on wider windows) with whole-pixel banners on `#0a0816`, the loader is contained and centred between the title band and a footer at the window's bottom, and the Home stage carousel uses the same viewport. Banner edges round half-up so a whole-pixel tile gives equal widths. Rendered at 1280x720 (loader 3x), 1920x1080 (4x, banners 1x), 2560x1080 (4x, more banners), 1000x1000 (4x) and 3840x2160 (9x, banners 2x).

Confirmed on the real Tk loop with an NES load: the sound playing at start, the game starting at 10.2 s.

Release 0.24.0 (2026-11-15) adds the owner's disc-loading sound to CD-console loads. `redux/assets/sounds/disc-load.mp3` (7.1 s) plays from `start_stage` for the seven CD systems through `redux/stage_sounds.py`, which drives Windows MCI (`mciSendString`, type mpegvideo) rather than winsound, so the MP3 needs no conversion and mixes with the menu sounds instead of being cut off by them. One stage sound at a time; a load already on the stage does not restart it; `clear_stage` (cancel, failure, leaving) and app shutdown stop and close it. It follows the Menu sounds setting. Confirmed on the real Tk loop (muted): MCI reports it playing at the start and three seconds in, and closed after a cancel.

Release 0.23.1 (2026-11-15) fixes the loader animation in real use and lengthens the stage to fifteen seconds. Pressing A on a disc that was not installed started the install without starting the stage, so Home fell back to the small banner view with a frozen first cell and a progress bar; `install_disc_from_drive(then_play=True)` now calls `show_stage` up front, a cancelled or failed install clears it, and a failed task clears it too. Release 0.23.0 (2026-11-15): the stage gets its moment. A game appears eight seconds after its load began (`STAGE_HOLD_SECONDS`): `hold_for_stage` polls on the Tk clock, starts the loader's outro at eight minus its length, and only then runs the core start (`_start_integrated_game`) or the PC launch (`_play_pc_game`); the banner always settles within 6.8 s and the loader's intro plus one loop take 4 s, so both fit. A stage that goes away while waiting drops the start instead of launching blind; without a window the start runs at once. Release 0.17.0 (2026-11-15) makes disc play intentional and one button. Play on an inserted disc installs it the first time (`install_disc_from_drive(..., then_play=True)`, into the library or the chosen extra storage) and starts it when the copy is done; after that it starts the installed copy at once. The library records the disc's fingerprint at install (new `disc_fingerprint` column, `set_disc_fingerprint`, `find_disc_game`), so an inserted disc is recognised before any reading; a managed CD game from before the column is matched by system and title and its fingerprint is recorded then. The home banner says Installed or Not installed and A plays (`play_disc`); the options menu is Play, Game information, Configure playback. `Library.play` checks once that a game installed from a disc (fingerprint, or legacy managed CD game) has that disc in the drive (`disc_requirement`) and stops with "Insert the disc" otherwise; nothing is checked during play, and games on cards and PC games never pass through it. Removed: playing from the drive through a temporary buffer (`play_inserted_disc`, `DiscEmbeddedGame`, the Pause → Install to library row, retained-lease handling) and the Install option everywhere; Media → Play a physical CD follows the same install-then-play rule and hosts Inspect disc tracks. Tests for buffered playback went with it (suite 825).

Release 0.16.0 (2026-11-15) gets BIOS files in from a drive and names what is missing. `redux/firmware_files.py` is the table of the firmware files Redux's emulators look for (name, system, region, subfolder, required or optional) and does three jobs: a drive that appears with a `bios`/`firmware` folder (root or inside `Redux Games`) holding known files gets one question after the card question, Copy N files or Not now (remembered by volume serial), and the copy lands each file where its emulator looks (`fbneo/neogeo.zip`, `neocd/...`), skipping identical files and never replacing a different one; `copy_firmware_menu` under Emulator setup offers the same for any connected drive; and the pre-launch check in `_start_integrated_game`, which only knew Saturn, now covers every system through `missing_firmware` (the game's region picks the file, any region's file is accepted when the region is unknown, Neo Geo also accepts `neogeo.zip` beside the game) and offers Choose firmware folder and Copy BIOS files from a drive. External backends' readiness uses the same table and gains Sega CD. When a core refuses a game anyway, `EmbeddedSession` quotes the core's last error line with its format directives stripped ("The libretro core refused this game: Unable to open CD BIOS."), which is what the owner's first Sega CD test produced with an empty bios folder.

Release 0.15.0 (2026-11-15) adds PC games on GOG to the shipped database. `redux/database/pc/games.json` holds every game GOG sells for Windows (7,718 games, built by the gitignored `tools/gamedb/fetch_gogdb.py` from the GOG DB daily dump of GOG's catalogue API, one 65 MB download instead of thousands of calls): title, year, developer, publisher, up to three genre tags and the store description as plain text, keyed by GOG product id. Release 0.14.0 (2026-11-14) makes game cards deliberate. Redux no longer writes to a drive because it appeared: a drive that arrives with no `Redux Games` folder gets one question (console cartridge, GOG cartridge, extra storage, or not now) and nothing is written before the answer; Not now is remembered by the drive's volume serial, and drives present at start-up are only read. Each kind writes only what it needs (`game_cards.prepare_card(drive, kind)`): a console cartridge gets one folder per cartridge system with an emulator (fifteen, Game Boy Advance excluded), a GOG cartridge gets `PC` and a `game.json` per installed GOG game (and again for new installs on every read, `write_pc_configs`), extra storage gets the seven CD system folders and can be the disc install destination. The kind is recorded in `Redux Games/card.json` (`card_kind`); cards from before 0.14 have no card file, are read as before and may still take disc installs. System → Storage shows each drive's kind and offers the same set-up for any drive; the Storage page, the rescan notice and the home-screen summary say so. The install destination is honoured only for an extra-storage or legacy card.
